PCB101 AI 求职助手交互规则说明

文档用途：供产品、设计、研发、测试及运营统一当前 H5 原型的交互口径。
依据版本：当前工作区前端原型（2026-07-24）。
说明：本文描述的是当前已实现行为，不等同于最终线上业务规则；文末列出了需要进一步确认的事项。

1. 产品目标与用户主路径

产品通过对话收集求职意向，逐步完成岗位匹配，并引导用户完善个人信息、查看岗位详情和投递。

主路径如下：

落地页
  → 微信登录/注册
  → 同意服务协议和隐私政策
  → 填写期望地区/城市
  → 选择 PCB 职业方向
  → 查看初步匹配结果
  → 补充细分岗位
  → 查看精准匹配结果
  → 填写或跳过个人信息
  → 查看岗位列表
  → 查看岗位详情
  → 投递或联系 HR

2. 全局交互规则

2.1 原型翻页

- 原型共 5 页，右侧显示当前页码。
- 支持点击左右翻页按钮。
- 支持键盘左右方向键翻页。
- 移动端支持左右滑动翻页；横向位移需大于 65 px，且明显大于纵向位移。
- 第 1 页禁用“上一页”，第 5 页禁用“下一页”。
- 翻页属于原型演示能力，不建议作为正式产品交互保留。

2.2 对话输入

- 用户可输入文字后点击“发送”。
- 按 Enter 可发送；中文输入法正在组词时按 Enter 不发送。
- 空内容不发送。
- AI 回复期间进入短暂忙碌状态，重复发送和重复触发语音无效。
- AI 回复后页面自动滚动到最新消息。
- 推荐词按钮只负责把文字填入输入框，不会自动发送。

2.3 模拟语音输入

- 点击麦克风后显示“正在聆听”状态。
- 约 1.5 秒后自动结束，并按当前对话阶段填入预设演示文本。
- 语音内容只填入输入框，不自动发送。
- 正在聆听或 AI 忙碌时，重复点击无效。
- 当前为演示逻辑，未接入真实语音识别。

2.4 返回规则

- 页面顶部返回按钮调用浏览器历史返回。
- 协议弹窗选择“拒绝”时：嵌入落地页的场景返回微信登录弹窗；独立打开助手时返回上一级目录。
- 职位详情中的顶部返回和底部“返回列表”均关闭详情页，回到当前岗位列表。

3. 分页面交互规则

3.1 第 1 页：落地页

页面展示产品能力、平台数据和“微信登录 / 注册”入口。

| 用户操作 | 系统响应 |
| 点击“微信登录 / 注册” | 打开微信登录弹窗，页面进入锁定状态 |
| 点击服务协议/隐私政策文字 | 当前仅跳转到页面锚点，无完整协议正文 |
| 点击顶部返回 | 浏览器历史返回 |

3.2 第 2 页：微信登录弹窗

| 用户操作/状态 | 系统响应 |
| 点击右上角关闭 | 关闭弹窗，回到落地页 |
| 未勾选协议，点击“微信一键登录” | 阻止进入；提示“请先阅读并勾选服务协议和隐私政策”；焦点移至复选框 |
| 勾选或切换复选框 | 恢复默认提示：“未注册的微信用户登录后将自动创建 PCB101 账号” |
| 已勾选协议，点击登录 | 进入第 3 页协议确认 |

账号规则：未注册的微信用户登录后自动创建 PCB101 账号。当前原型未接入真实微信授权和账号系统。

3.3 第 3 页：服务协议和隐私政策确认

- 弹窗为强制阻断层，未处理前不能继续助手流程。
- 点击“同意并继续”进入第 4 页。
- 点击“拒绝”返回第 2 页微信登录弹窗。
- 协议正文链接目前仍为占位锚点。

3.4 第 4 页：地区意向首次询问

AI 询问用户希望发展的地区或城市，支持大区、国家、具体城市和多地点表达。

地区识别规则

- 支持的大区/国家：华南、华东、华中、西南、华北及东北、港澳台、马来西亚、泰国、越南、新加坡、墨西哥、欧洲、美国。
- 输入具体城市时，从预设城市词表中提取；支持一次输入多个城市，结果去重并用“、”连接。
- 输入已配置的大区或国家后，继续询问该区域内的优先城市。
- 输入“都可以”时，保留当前大区，不再要求确认具体城市，直接进入职业方向。
- 无法识别时提示：“暂未识别到预设地区或城市，请换一种方式描述。”
- 当前“不限地区”“海外机会”虽然作为推荐词展示，但没有对应识别规则，会进入无法识别分支。

华南演示特例

- 识别为“华南/华南地区”后，当前原型会跳转到第 5 页，再展示华南城市追问。
- 原始输入暂存于当前浏览器会话中，用于在第 5 页还原对话。
- 这是原型分镜规则，不是业务上必须单独跳页的规则。

具体城市确认

| 用户回复 | 系统响应 |
| 肯定表达 | 确认地区，进入职业方向 |
| 否定表达 | 清空当前确认流程，请用户重新描述地区/城市 |
| 其他表达 | 提示用户回复“是”或“不是” |

肯定表达包括“是、对、正确、没错、可以、确认、确定、好、没问题、yes、y”等；否定表达包括“不是、不对、错误、有误、否、不要、不需要、no、n”等。系统会忽略常见标点、空格、开头语气词和末尾部分语气词。

3.5 第 5 页及后续：职业方向和岗位匹配

A. 职业方向

系统展示 10 类职业方向：

1. 研发/产品/技术类
2. CAM/MI/设计类
3. 工艺/制程/制造工程类
4. 品质/体系/客户质量类
5. 生产/运营/PMC类
6. 设备/自动化/厂务类
7. 采购/供应链/物流类
8. 销售/市场/客户服务类
9. 职能支持类
10. 经营管理类

- 回复 1～10：直接选择对应类别，不再二次确认。
- 自由文本中明确包含 CAM 或 MI：识别为“CAM/MI/设计类”，并要求确认。
- 其他所有自由文本：默认识别为“工艺/制程/制造工程类”，并要求确认。
- 确认错误时返回职业方向选择；非肯定/否定回答则继续要求明确确认。

当前自由文本识别只完整区分 CAM/MI 与工艺制程，尚不能准确识别其余 8 类职业方向。

B. 初步匹配

- 职业方向确定后显示“根据地区和工种初步匹配：535 个岗位”。
- 询问用户是否愿意继续补充信息。
- 回复“愿意/是/继续/精准/补充”等：进入细分岗位询问。
- 回复“否/直接看岗位/先看看”等：直接展示当前职业方向对应的岗位列表。
- 其他回复：提示用户在“继续精准匹配”和“直接看岗位”之间选择。

C. 细分岗位

- CAM/MI/设计类：支持从输入中提取 CAM、MI、DFMT/DFM、Gerber、PCB 设计、Layout、阻抗/抗阻、拼版、菲林、工程资料及部分主管/经理岗位；可识别多个岗位并去重。
- 工艺/制程类：页面展示制程、工艺、压合、钻孔、电镀、蚀刻、阻焊、AOI、SMT、电测、表面处理及主管/经理等参考岗位。
- 推荐词点击后只填入输入框，仍需用户发送。
- 当前工艺/制程类无论用户实际输入什么，都会写入预设演示岗位“工艺工程师、制程工程师、阻焊工程师”。
- 提交细分岗位后直接显示“精准匹配 48 个岗位”，不再做岗位确认。

D. 个人信息选择

精准匹配后询问是否愿意填写个人基本信息。

| 用户选择 | 系统响应 |
| 愿意填写 | 打开个人信息弹窗 |
| 暂不填写/跳过/先看 | 展示岗位列表；前 3 个可浏览，其余显示锁定 |
| 其他回答 | 提示回复“是”或“暂不填写” |

4. 个人信息弹窗

4.1 字段与校验

以下字段均为必填，依赖浏览器原生表单校验：

| 字段 | 类型/选项 |
| 姓名 | 文本输入 |
| 性别 | 男、女 |
| PCB 行业工作年限 | 0-1年、1-3年、3-5年、5-10年、10年以上 |
| 学历 | 高中/中专、大专、本科、硕士及以上 |
| 目前公司名称 | 文本输入 |
| 目前岗位名称 | 文本输入 |

4.2 操作结果

- 点击关闭或“暂不填写”：关闭弹窗；如尚未展示岗位，则展示受限岗位列表。
- 填完后点击“确认并查看全部岗位”：关闭弹窗，提示个人信息已确认，并解锁全部岗位。
- 从锁定岗位触发弹窗时，提示语改为“填写基本信息后可以查阅并投递所有岗位”。
- 当前数据只保存在页面运行状态中，刷新后不会保留，也未提交到后端。

5. 岗位列表规则

- 当前按职业方向展示两套演示数据：CAM/MI/设计类岗位，或工艺/制程类岗位。
- 每套演示列表各 8 条，但标题固定显示“精准匹配 48 个”。
- 已填写个人信息：点击任意岗位打开职位详情。
- 未填写个人信息：前 3 条视觉上不锁定，其余条目显示“填写信息后查看”。
- 当前实现中，只要列表处于受限模式，点击任意岗位（包括前 3 条）都会打开个人信息弹窗，不能打开详情。

6. 职位详情规则

- 点击可访问的岗位后，以全屏层展示详情。
- 职位名称、薪资、城市、经验、学历、公司及标签来自所点击的岗位卡片。
- 岗位简介由职位名称动态拼接；福利、职责、任职要求和公司介绍主体为统一演示文案。
- 点击“一键投递”：按钮文字变为“已投递”。
- 点击“立即沟通”：按钮文字变为“已发起沟通”。
- 当前没有二次确认、撤销、失败重试、登录态校验或真实网络请求。
- 关闭详情后再次打开岗位，两个操作按钮会恢复为初始文案。

7. 对话状态与容错口径

| 对话阶段 | 有效输入 | 无效/模糊输入处理 |
| 地区识别 | 已配置大区、国家或城市 | 提示换一种方式描述 |
| 城市确认 | 肯定或否定表达 | 要求回复“是”或“不是” |
| 职业方向 | 1～10 或自由描述 | 自由描述默认归入 CAM/MI 或工艺制程后确认 |
| 是否继续精准匹配 | 愿意/继续，或直接看岗位 | 提示二选一 |
| 细分岗位 | 任意非空岗位描述 | 当前无非法岗位拦截 |
| 是否填写个人信息 | 愿意填写，或暂不填写 | 提示二选一 |
| 岗位浏览 | 点击岗位 | 根据是否受限进入详情或信息弹窗 |

补充规则：

- 用户输入在显示到页面前会进行 HTML 转义，避免直接注入标签。
- AI 忙碌时发送的内容不会排队，也不会提示失败。
- 当前没有网络异常、服务超时、登录失效、数据保存失败等异常态。

8. 当前原型中的固定演示数据

以下数字和内容目前为前端写死，不是实时计算结果：

- 初步匹配：535 个岗位。
- 精准匹配：48 个岗位。
- 另一套未接入当前主路径的匹配卡：353 个岗位。
- 旧对话分支中的进一步筛选结果：45 个岗位。
- 岗位列表：每个职业方向实际展示 8 条。
- 默认个人画像：深圳、苏州；工艺/制程/制造工程类；10 年经验；博敏电子；工艺主管。

9. 待产品/研发确认项

以下事项建议在进入正式开发前统一：

1. 协议是否需要在微信登录前后重复确认；协议正文和隐私政策的实际承载方式是什么。
2. “不限地区”“海外机会”的识别及后续城市追问规则。
3. 10 类职业方向的完整文本识别词典、兜底策略和置信度规则。
4. 初步匹配 535、精准匹配 48、旧分支 353/45 等数字的真实计算口径。
5. 不填写个人信息时，前 3 个岗位究竟是“可看详情但不可投递”，还是完全不可进入详情。
6. 点击任意锁定岗位是否都应拉起信息弹窗，以及完成填写后是否回到用户刚才点击的岗位。
7. 个人信息的存储、修改、脱敏、授权撤回及隐私合规规则。
8. 投递与沟通的登录校验、确认、结果反馈、失败重试和防重复提交规则。
9. 推荐词点击后是仅填入输入框，还是应直接发送以减少操作步骤。
10. AI 忙碌期间再次发送时，是禁用输入、排队，还是明确提示用户稍候。

10. 建议验收用例

1. 未勾选协议点击微信登录，应被阻止并看到错误提示。
2. 同意登录协议后进入助手；拒绝隐私协议后返回登录弹窗。
3. 输入“深圳和苏州”，应识别两个城市并要求确认。
4. 输入“华南”，应进入华南城市选择；回复“都可以”后进入职业方向。
5. 地区确认时回复模糊文本，应要求明确回答“是/不是”。
6. 职业方向回复“2”，应直接选中 CAM/MI/设计类并展示初步匹配。
7. 回复“我做 CAM 和阻抗”，应识别 CAM工程师、阻抗设计工程师。
8. 初步匹配后回复“直接看岗位”，应跳过细分信息并显示岗位列表。
9. 精准匹配后选择暂不填写，应出现受限岗位列表。
10. 完整填写个人信息后，应解锁全部岗位并可进入详情。
11. 在详情页点击投递/沟通，按钮状态应分别更新。
12. 文字输入包含 HTML 标签时，应以普通文本展示，不执行标签。
